# 飞书提示词 → 仓库更新 SOP

适用仓库：`awesome-gpt-image-2.5-prompts`。本流程接在 `collect-seeapi-prompts` 的采集、去重、图片核对和飞书候选录入之后。采集完成不等于批准公开发布。

## 1. 读取现状

1. 阅读本仓库维护指南、来源规范、catalog、案例模板和最近更新日志；检查 Git 工作区，保留其他人的改动。
2. 使用 `lark-cli base +url-resolve` 解析用户提供的飞书链接，读取真实字段结构。按用户指定视图获取候选；需要全表去重时另读整张表，不能把视图当全表。
3. 在获得本次内部资料读取/本地暂存许可后，分页读取并保存成功响应、读取范围、时间及分页终止证据。检查 `ok == true`，直到 `has_more=false` 或明确终止信号。不得以默认第一页声称全量。
4. 原始表格、编辑备注、审核人、附件临时链接和操作回执保存在仓库外的内部批次目录，不能随公开仓库提交。

## 2. 筛选和核对

- 尊重人工审核：`跳过` 不收录，`待补全` 保留具体缺项；`待审核` 可准备本地草稿，但不能擅自改成 `通过`。发布前向用户列出本次拟发布清单及待审核项。
- 去重使用规范化来源 URL + 页面内条目标识、规范化 Prompt 哈希、素材 SHA-256。一个聚合页面可以包含多个条目，不能只按整页 URL 去重。已发布条目保留 ID 和 slug；本地未发布草稿若与新拉取的远端编号冲突，应顺延到空闲编号，同步 slug、文件路径、交叉引用和内部回写映射。
- 原 Prompt 按原语言逐字保存，标题用简洁英文；短模板明确标为模板，不称作效果图完整生成输入。
- 原作者、采集页面发布者、灵感作者和效果图来源分别记录。飞书“来源发布者”不是原作者的自动证明；沿页面署名和原帖核对。
- 缺来源时写 `Original source unconfirmed`，缺作者写 `Author unconfirmed`；不能默认写 SeeAPI，也不能把内部飞书链接当公开出处。保留可核实的收集页面链接和未确认项。
- 逐张查看实际图片，核对主体、构图、文字、数量以及输入/输出角色。收集图不等于仓库实测图；来源页面的模型声明不等于独立验证。
- 原图与优化预览分开保存，不去水印。来源署名不等于复用许可；公开分发前核对具体素材范围，未明确的项目在发布清单中指出。

## 3. 本地更新

1. 新独立提示词在拉取并合并远端后，从当前最大 P 编号递增（本次已到 P40，下一个是 P41）；C07–C10 保留给创意系列，不能拿采集内容凑数。
2. 先写 `prompts/{slug}/*.txt`，再同步 `cases/{slug}.md`、README 全文块及 `catalog.json`。README 继续保留 👀 Preview、👇 Workflow、🔖 Full Prompt，并将图片按比例限制在 400 × 400 显示范围；新增条目倒序放在 Prompt Directory。
3. 每个外部案例在标题下显示 作者署名链接和 Source 原帖链接；来源不确定时明确注明。目录保持指向案例正文的稳定锚点，同时展示作者与来源链接。
4. catalog 的 `author` 记录实际 Prompt 作者，`inspiration` 仅记录灵感；新增 `source` 记录收集出处，字段为 `url`、`publisher`、`author_status`、`relationship`。`relationship` 使用 `collected` 或 `adapted`；`author_status` 使用 `credited-by-source` 或 `unconfirmed`，不得冒充独立确认。
5. 实际媒体放 `assets/{slug}/`。状态只说明仓库包含何种素材，不暗示模型已实测。同步分类、总数、日期、来源说明和 CHANGELOG。
6. 内部批次账本记录飞书记录 ID、候选 ID、仓库 ID、Prompt/素材哈希、拟发布路径和核对结论；公开文件不含内部人员、记录快照或下载凭据。

## 4. 验收和发布

运行：

```bash
python3 scripts/validate_catalog.py
git diff --check
git diff --stat
```

逐项检查正文、纯文本和 README 一致，来源及署名一致，锚点有效；预览 Markdown，查看新增素材，不以脚本检查替代视觉核对。汇报已读范围、新增/更新/重复/暂缓数量及具体原因。

向用户展示具体拟发布改动，并在公开 push 或其他立即影响公开行为的操作前获得当前对话中的明确确认。未获确认时停在可审阅的本地改动，不标记已发布。

发布后读取远端确认提交和文件可访问，再按准确记录 ID 回写 `GitHub链接` 和 `发布状态=已发布`；如果该保存会触发其他生产流程，先确认影响和授权。不得覆盖审核人、人工审核状态或编辑备注。回写失败单独记录；重试前读取现状，不能再次新增相同候选。

## 5. 接入后续采集工作流

每次采集收尾增加“仓库交接”步骤：检查本 SOP，读取 catalog 去重，输出适合收录的候选和缺项，准备授权范围内的本地更新。飞书仍是内部审核队列，仓库是公开展示目标。

更新已有采集技能或定时任务时，在其收尾指向本 SOP，并保留采集原文、图片核对和发布确认边界；不要创建重复的采集任务或自动公开推送。技能/任务配置的实际更新与 SOP 文档完成分别验收，不能只写了本文就声称调度已接通。

当前已在 `collect-seeapi-prompts` 技能中加入 Repository handoff after collection，并指向本文。技能接线已完成；本次未修改定时任务的时间、启停或权限。

合并校验需检查真正的 Markdown 标题锚点，不仅检查链接文字是否存在。创意案例标题含署名时，锚点随完整标题计算；归档案例的回链指向仍存在的正文或目录。合并后当前为 5 个活跃创意流程 + 40 个独立提示词，C03 的归档文件保留。
