# SeeAPI 提示词库设计方案

这套仓库以“看见效果 → 找到玩法 → 复制完整提示词 → 按参考图要求复现”为主线。首页承担展示与导航，案例页承担完整教学，独立文本文件方便复制与长期维护。

按最新讨论，本版暂不放 SeeAPI 在线体验、API 或控制台链接。品牌露出保留在简介与原创提示词署名中；有来源或灵感链接的案例同时保留原作者署名。暂不开放外部投稿。

## 3. 统一案例页

每个案例按相同骨架组织：

- **英文标题与固定 ID**：例如 `C06. Frosted Glass Poster to 360° Orbit`。
- **作者、灵感、分类与更新时间**：原创写 `by SeeAPI`；灵感来自帖子时加 `inspired by` 与原帖链接。
- **Preview**：真实效果图或 GIF；明确它是参考图、首帧、分镜还是最终结果。暂缺效果图时直接注明，不放假图。
- **Reference Images**：必需/可选数量、上传顺序、身份图与首尾帧的角色；纯文生图写明无需参考图。
- **Full Prompt & Workflow**：完整可复制英文 Prompt；多阶段案例分步写输入、操作、输出，负面提示词独立展示。
- **Prompt Files**：链接纯文本版本，方便下载与复用。
- **Sources & Attribution**：记录 Prompt 作者、灵感作者、示例素材来源、已知生成模型和许可范围；最后返回首页。

现有 C03–C06 的详细中文制作说明保存在 `docs/production/`，由英文案例页链接进入。已知生成偏差和验收要点保留，例如大象动作跳变、手部对应、花盆位置、杯柄与文字稳定性。

可复用的模板见 [case.md](../templates/case.md)。本版模板没有产品入口。

## 4. 文件组织与持续更新

采用 `cases/`、`prompts/`、`assets/` 三类路径，使用相同 slug 对应一个案例。创意流程沿用原有 `01-pixel-art-gif` 等命名以保持图片与脚本路径稳定，独立提示词使用 `p01-personalized-sticker-pack` 等命名。

`catalog.json` 记录 ID、分类、作者、来源、完成状态、详情与素材路径。它为维护检查提供索引；当前首页仍手动编辑，不宣称已实现自动生成。完整规则见 [目录结构](repository-structure.md)。

新增内容按模板补齐 Prompt 和来源后即可以“Prompt only”发布；生成并审查效果后再更新状态。每次更新同步首页目录、日期、目录元数据和更新日志。建议每周检查候选内容、每月调整精选与分类，但本次没有创建定时任务。
